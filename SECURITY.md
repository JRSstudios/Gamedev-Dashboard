# Security

## Reporting
Please report vulnerabilities privately via GitHub's "Report a vulnerability" (Security tab) instead of a public issue.

## Design
- Everything stays on your machine, with one optional exception: the Claude commands you trigger yourself send a project summary to Anthropic (see below). No telemetry, no remote content, strict Content-Security-Policy.
- Tauri capabilities are minimal (dialogs, window state). File access goes through a few Rust commands: atomic save of `data.json`, existence checks, size/type-limited previews of image/audio files, and export/import limited to `.json`/`.md` paths chosen in native dialogs.
- Stored and imported JSON is validated with a schema and size limits before use; invalid data is never overwritten silently.
- Linked asset paths are only read for previews, never executed.
- Claude (desktop only, optional): the Anthropic API key is stored in the OS credential store (Windows Credential Manager, macOS Keychain, Linux keyutils) and is only read by the Rust backend, which sends requests to `https://api.anthropic.com/v1/messages` and nowhere else. The key never enters the webview, `data.json`, exports or logs. Requests contain a text summary of the active project (titles, names, notes), never file contents or paths. Responses are validated and applied only after confirmation. The web demo has no Claude feature.
- Unity / Blender transfer (desktop only): files are copied, never moved; an existing file is only replaced when you turned on "auto import … and copy into Unity" and the same export arrives again. Otherwise nothing is overwritten (a `-1` copy is made). Targets are limited to folders you linked; sub folders cannot contain `..` or absolute paths and symlink escapes are rejected; the Unity target must contain `Assets` and `ProjectSettings`. Programs are only started if the executable is named `Unity` / `blender`, without a shell or free-form arguments.
- 3D preview and Krita (desktop): model files are read only for `glb/gltf/bin/fbx/obj/mtl/png/jpg` up to 200 MB, and the textures/buffers of a glTF only from inside the model's own folder. `.kra` previews read just the `mergedimage.png` entry of the archive. Converting `.blend` runs the Blender you linked (executable must be named `blender`) with a fixed export script and writes only into the app's cache folder; Krita is only started when the executable is named `krita`.
- Plugin bridge (desktop, can be switched off in Settings): a small HTTP server listens only on `127.0.0.1` with a random port and a random 192-bit token, both written to `bridge.json` in the app data folder (readable by your user only). Every request needs the token (compared in constant time); requests with an `Origin` header (web pages) are rejected; bodies are limited to 256 KB and requests to 60 per second. Plugins can only report fixed event types (exported, model check, Unity log/compile/scenes) and fetch fixed job types (import, refresh, create prefab, open scene, build, export, check, apply transforms, origin to floor, LODs, export collections, export layers, sprite sheet). Nothing sent over the bridge is executed as code.
- Plugins (Unity package, Blender add-on, Krita plugin) are installed only when you click "Install": the Unity package goes into `Packages/com.gamedev-dashboard.bridge` of the linked project, the Blender add-on into each `…/Blender/<version>/scripts/addons/gamedev_dashboard`, the Krita plugin into `pykrita/gamedev_dashboard`. "Remove" deletes exactly these folders. The plugins only talk to `127.0.0.1` and only touch files they export themselves or that the dashboard copied.
- Claude usage: each request stores model, command name and token counts for the cost overview, never prompt text.
- Links: only `http(s)` URLs are stored and opened (via the system browser); the app never fetches them.
- Local AI: only talks to the `http(s)` server you configure (normally `localhost`). Model output is validated, treated as untrusted suggestions and applied only after confirmation. Asset names and notes sent to the model are data, not instructions.
- Claude Code (desktop, optional): instead of an API key the app can start your installed `claude.exe` (found on `PATH` or in `~/.local/bin`; `.cmd` wrappers are never run) with a fixed argument list: print mode, JSON output, **all tools disabled** (`--tools ""`), one turn, no session file, no MCP servers, in an empty temporary folder. The prompt goes in over stdin, the model name is checked to contain no flags, and the run is stopped after 4 minutes. Claude Code handles its own sign-in; the app never sees a login or token.
- Templates: the catalog is downloaded only from `raw.githubusercontent.com/JRSstudios/Gamedev-Dashboard/main/templates/` (fixed in Rust, only `index.json` and `<name>.gdtemplate.json`, 1 MB limit, no redirects). Templates are data, validated with a schema; C# scripts in them are shown in full and written only on click into `Assets/Scripts/Templates` of the linked Unity project, never over an existing file. Exported templates contain only texts (no paths, files, notes or logged time).
- Snapshots: a copy of `data.json` is kept once a day in the app data folder (`snapshots/data-YYYY-MM-DD.json`, last 14); with a backup folder chosen, the same copy goes there as `gamedev-dashboard-YYYY-MM-DD.json`. Only files with exactly these names are ever deleted.
- Global shortcut: `Ctrl+Shift+Space` only brings the window to the front and opens the quick note.
- Plugin helpers run fixed code inside Blender/Krita/Unity (apply transforms, origin, LODs, batch export, sprite sheet, build); no code is sent from the app.
- Release installers are currently unsigned.
